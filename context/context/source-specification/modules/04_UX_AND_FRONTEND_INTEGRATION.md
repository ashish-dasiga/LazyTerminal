# Module 04 — UX, Screen Behaviour, and Frontend Integration

## 4.1 Required app flow
- Before connection: show a connection screen asking for the current secret generated by the PC.
- After successful connection: open the terminal directly.
- Do not route the user to a home dashboard with separate large cards for Terminal, Explorer, and Editor.
- Keep navigation compact and persistent.

## 4.2 Connected workspace
The terminal is the main work surface. A compact top bar or persistent menu exposes:
- Explorer
- Terminal (active/default)
- Source Control
- CLI launcher / Run
- Preview
- More Options / Settings

Editor may open as a panel or workspace view, but terminal and navigation context should remain easy to return to. The exact UI should follow the supplied frontend artifact where possible.

## 4.3 Mobile-specific rules
- Do not show macOS red/yellow/green window controls.
- Do not make the interface look like a desktop browser window.
- Make terminal input and output usable on a phone screen.
- Handle keyboard visibility and scrolling.
- Provide clear connection, execution, offline, syncing, success, and error indicators.
- CLI activity must not remove all navigation.
- Respect Android back/navigation behaviour.

## 4.4 Frontend handoff
Two frontend contributors are preparing:
1. Terminal/connected-workspace frontend.
2. Connection screen frontend for Android and PC.

The user will supply a `.dht` file. At Phase 0:
- Inspect the file's actual contents and format.
- Preserve the original file.
- Identify framework/runtime and integration constraints.
- Do not assume `.dht` means any particular language or framework.
- Do not invent a replacement frontend if the file is not yet present.
- If it is a design-only export, document what conversion is required.
- Keep real protocol/business logic out of purely visual components.

## 4.5 UI state model
At minimum:
- `disconnected`
- `connecting`
- `pairing_rejected`
- `connected_idle`
- `terminal_running`
- `cli_running`
- `pc_unavailable`
- `offline_queue_pending`
- `sync_review_required`
- `syncing`
- `conflict`
- `error`

## 4.6 Acceptance
The frontend handoff is inventoried, preserved, and integrated with real application state. The terminal is the default connected screen and navigation remains accessible during CLI use.
